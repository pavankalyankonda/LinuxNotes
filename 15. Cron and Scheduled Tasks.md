# 15. Cron and Scheduled Tasks

## 15.1 What is cron?

**cron** is a background scheduling service (daemon) that runs commands or scripts according to time-based schedules.

A **cron job** is a scheduled command or script. A user's **crontab** contains that user's scheduled jobs.

| Term | Meaning |
|---|---|
| cron | Background scheduling daemon |
| crontab | Table/configuration of scheduled jobs |
| `crontab` command | Command used to manage a user's crontab |
| cron job | A scheduled command or script |

## 15.2 Common crontab commands

```bash
crontab -l                  # List your cron jobs
crontab -e                  # Edit your cron jobs
crontab -r                  # Remove all your cron jobs
crontab -u username -l      # List another user's crontab (with permission)
sudo crontab -e             # Edit root's crontab
sudo crontab -l             # List root's crontab
```

**Warning:** `crontab -r` removes the current user's entire crontab. Use it carefully.

## 15.3 Cron schedule format

A standard user crontab entry has five time fields followed by the command:

```text
┌──────── minute (0–59)
│ ┌────── hour (0–23)
│ │ ┌──── day of month (1–31)
│ │ │ ┌── month (1–12)
│ │ │ │ ┌ day of week (0–7; Sunday is 0 or 7)
│ │ │ │ │
* * * * * command-to-run
```

## 15.4 Special characters

| Symbol | Meaning | Example |
|---|---|---|
| `*` | Every allowed value in the field | `* * * * *` |
| `,` | A list of values | `0 9,18 * * *` |
| `-` | A range | `0 9 * * 1-5` |
| `/` | A step/interval within a field | `*/5 * * * *` |

### Why does `/` mean an interval?

Think of `/` as **step by**.

For example:

```cron
*/5 * * * * /path/to/script.sh
```

The minute field has values from 0 to 59. `*/5` selects every fifth step through that range:

```text
00, 05, 10, 15, 20, 25, 30, 35, 40, 45, 50, 55
```

`*/1` means every one minute, which is equivalent to `*` in that field.

### Common schedules

| Cron expression | Meaning |
|---|---|
| `* * * * *` | Every minute |
| `*/1 * * * *` | Every minute |
| `*/2 * * * *` | Every 2 minutes |
| `*/5 * * * *` | Every 5 minutes |
| `*/10 * * * *` | Every 10 minutes |
| `*/15 * * * *` | Every 15 minutes |
| `*/30 * * * *` | Every 30 minutes |
| `0 * * * *` | At the start of every hour |
| `0 */2 * * *` | At minute 0, every 2 hours |
| `30 9 * * *` | Every day at 09:30 |
| `0 2 * * *` | Every day at 02:00 |
| `0 9 * * 1-5` | At 09:00, Monday through Friday |
| `0 2 * * 0` | At 02:00 every Sunday |
| `0 0 1 * *` | At midnight on the first day of each month |

### Starting at a particular value: `5/10`

```cron
5/10 * * * * date
```

In common cron implementations, this means start at minute 5 and step by 10:

```text
05, 15, 25, 35, 45, 55
```

Cron implementations can differ in some less-common syntax details. For portable schedules, prefer widely supported forms.

## 15.5 Can cron run a command every 30 seconds?

Traditional cron has **one-minute resolution**; it does not have a seconds field.

A practical workaround is to run the command twice during each minute:

```cron
* * * * * /path/to/command
* * * * * sleep 30; /path/to/command
```

This runs once near the start of the minute and once about 30 seconds later. The second invocation can be delayed if the system is busy or the first command is still running.

For example, to append timestamps:

```cron
* * * * * date >> /tmp/cron.log
* * * * * sleep 30; date >> /tmp/cron.log
```

For more precise or reliable sub-minute scheduling, use a long-running process, a suitable scheduler, or a systemd timer/service design rather than relying on cron.

## 15.6 Test a cron job

Edit the crontab:

```bash
crontab -e
```

Add:

```cron
* * * * * date >> /tmp/cron-output.log
```

Verify:

```bash
crontab -l
```

Wait a minute, then inspect:

```bash
cat /tmp/cron-output.log
```

## 15.7 Cron service and logs on Ubuntu

```bash
sudo systemctl status cron
sudo systemctl start cron
sudo systemctl enable cron
sudo grep CRON /var/log/syslog
```

Depending on system configuration, cron logs may be available through journald:

```bash
sudo journalctl -u cron
```

## 15.8 Important production considerations

Cron runs with a limited environment. Use:

- Absolute paths to scripts and commands.
- Correct executable permissions.
- Explicit environment variables when required.
- Output redirection so failures can be investigated.
- Locking or another mechanism if overlapping runs would be harmful.

Example:

```cron
0 2 * * * /home/konda/backup.sh >> /home/konda/backup.log 2>&1
```

`>>` appends standard output. `2>&1` sends standard error to the same destination.

Special shortcuts supported by common cron implementations:

```cron
@reboot  /path/to/startup-script.sh
@hourly  /path/to/hourly-script.sh
@daily   /path/to/daily-script.sh
@weekly  /path/to/weekly-script.sh
@monthly /path/to/monthly-script.sh
@yearly  /path/to/yearly-script.sh
```

Cron generally does not automatically catch up on jobs missed while a machine was powered off. For catch-up scheduling, investigate anacron or systemd timers.

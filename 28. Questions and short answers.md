## Questions and short answers

### Q1. What is the difference between a program and a process?

A program is executable code stored on disk. A process is a running instance of that program, managed by the operating system and identified by a PID.

### Q2. What is the difference between a process and a job?

A process is an OS-managed execution instance with a PID. A job is a shell-level unit of work managed by a particular shell and identified by a job number.

### Q3. What is a daemon?

A daemon is generally a long-running background process that provides a system or application function, such as an SSH server.

### Q4. What is systemd?

systemd is a system and service manager. On a typical Ubuntu system it runs as PID 1 and manages services and other units.

### Q5. What is the difference between `systemctl` and `journalctl`?

`systemctl` controls and inspects systemd units. `journalctl` reads and filters logs collected by systemd-journald.

### Q6. What is initramfs?

initramfs is a temporary early-userspace environment loaded during boot. It provides tools and drivers that may be needed to locate and prepare the real root filesystem.

### Q7. What is the difference between `df` and `du`?

`df` reports filesystem-level capacity and free space. `du` estimates the disk usage of files and directories.

### Q8. What is the difference between `apt update` and `apt upgrade`?

`apt update` refreshes package indexes. `apt upgrade` upgrades installed packages using the available package information.

### Q9. What is the difference between a hard link and a symbolic link?

A hard link is another name for the same inode. A symbolic link stores a pathname to its target and can become broken if the target path disappears.

### Q10. What does `chmod 755` mean?

The owner has read, write and execute permissions. The group and others have read and execute permissions.

### Q11. What is umask?

umask removes permissions from the default creation modes for new files and directories.

### Q12. Can cron run a job every 30 seconds?

Traditional cron schedules at minute resolution. A common workaround is two invocations per minute, with the second delayed by `sleep 30`. For precise sub-minute scheduling, use a more suitable scheduler or service design.

### Q13. How do you check whether a port is listening?

Use `ss`, for example `sudo ss -lntp` for listening TCP sockets.

### Q14. How do you troubleshoot a failed service?

Check `systemctl status SERVICE`, inspect `journalctl -u SERVICE`, validate configuration, and verify dependencies such as networking, storage and ports.

### Q15. Why should `kill -9` not be the first choice?

SIGKILL prevents the process from performing normal cleanup. Try a graceful stop through the service manager or SIGTERM first.

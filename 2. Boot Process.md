# 2. Linux Boot Process

The **boot process** is the sequence of steps that takes a machine from power-on to a usable operating system.

## 2.1 Boot sequence

```text
POWER ON
   |
   v
BIOS / UEFI
   |  Initializes hardware and selects a boot device
   v
BOOTLOADER (commonly GRUB)
   |  Loads the Linux kernel and initramfs into memory
   v
LINUX KERNEL
   |  Initializes CPU, memory, drivers and core kernel facilities
   v
INITRAMFS
   |  Temporary early userspace helps locate and prepare the real root
   v
REAL ROOT FILESYSTEM (/)
   |  The actual operating-system filesystem becomes available
   v
INIT PROCESS (normally systemd on Ubuntu)
   |  PID 1
   v
SYSTEMD TARGETS AND UNITS
   |  Starts required services and other units
   v
SSH / NETWORKING / LOGGING / APPLICATIONS
   |
   v
SYSTEM READY
```

### Step 1: BIOS or UEFI

Firmware starts when the device is powered on. It performs basic hardware initialization and selects a boot device according to its boot configuration.

### Step 2: GRUB bootloader

GRUB is a commonly used Linux bootloader. It loads the selected Linux kernel and the initramfs image into RAM, then transfers control to the kernel.

### Step 3: Linux kernel

The kernel initializes core operating-system functionality, including:

- CPU and memory management
- Device drivers
- Process and scheduling infrastructure
- Filesystem support
- Networking foundations

### Step 4: initramfs

**initramfs** means *initial RAM filesystem*. It is a temporary early-userspace environment loaded into memory during boot.

It can contain drivers, modules, tools and scripts required to find and prepare the real root filesystem.

### Why is initramfs needed?

Imagine the real root filesystem `/` is stored on an LVM logical volume:

```text
Physical disk
    |
    v
LVM physical volume
    |
    v
LVM volume group
    |
    v
Logical volume
    |
    v
Filesystem (for example, ext4)
    |
    v
Real root filesystem (/)
```

The kernel must access the real `/` to continue normal startup. But it may first need tools or drivers to activate LVM, assemble RAID, unlock encrypted storage or load a storage driver.

If those tools were available only inside the real `/`, the machine would face a chicken-and-egg problem: it needs `/` to get the tools, but needs the tools to access `/`.

initramfs solves this by providing a small temporary environment containing the required early-boot tools.

### Step 5: Real root filesystem

After the required storage is discovered and prepared, the system mounts the real root filesystem and transitions away from the temporary initramfs environment.

### Step 6: systemd

On a typical modern Ubuntu system, the kernel starts `systemd` as the initial userspace process. It normally has **PID 1**.

systemd starts and manages the units needed to bring the system to its configured state, including services, mounts, sockets and targets.

## 2.2 Inspect the booted system

```bash
ps -p 1 -o pid,comm,args     # Identify PID 1
systemctl status             # Show overall system state
systemd-analyze              # Show boot timing summary
systemd-analyze blame        # Show time spent starting units
journalctl -b                # Logs from the current boot
```

**Troubleshooting idea:** If a machine boots but a service is unavailable, inspect the service state and its boot logs:

```bash
systemctl status ssh
journalctl -b -u ssh
```

# 5. Programs, Daemons, Services and systemd

## 5.1 What is systemd?

**systemd** is a system and service manager used by modern Ubuntu systems. It normally runs as PID 1 and manages the units needed to initialize and maintain the userspace system.

A **unit** is a resource or task that systemd can manage. Common unit types include:

- `.service` — services
- `.socket` — sockets
- `.mount` — mount points
- `.timer` — scheduled activations
- `.target` — groups of units representing a system state

## 5.2 What is systemctl?

`systemctl` is the command-line tool used to inspect and control systemd units.

```bash
systemctl status ssh       # Show SSH service status
sudo systemctl start ssh   # Start SSH now
sudo systemctl stop ssh    # Stop SSH now
sudo systemctl restart ssh # Restart SSH
sudo systemctl reload ssh  # Ask service to reload configuration, if supported
sudo systemctl enable ssh  # Enable automatic start at boot
sudo systemctl disable ssh # Disable automatic start at boot
```

**Start vs enable:**

- `start` affects the service now.
- `enable` configures it to start automatically during boot.
- `enable --now` does both.

```bash
sudo systemctl enable --now apache2
```

## 5.3 Service executable and service unit

For SSH on Ubuntu, common locations include:

```text
/usr/sbin/sshd
    The SSH server executable (program)

/usr/lib/systemd/system/ssh.service
    Packaged systemd service-unit definition
    (On some systems /lib is a link to /usr/lib.)

/etc/systemd/system/
    Local administrator unit files and overrides
```

The service name on Ubuntu is commonly `ssh`; on some other distributions it may be `sshd`.

Inspect the actual unit path on your machine:

```bash
systemctl cat ssh
systemctl show -p FragmentPath ssh
command -v sshd
```

## 5.4 Why are there files under `/etc/systemd/system`?

`/etc/systemd/system` is intended for local administrator configuration. It can contain locally created units, symlinks and overrides for packaged units.

For an existing service, prefer a systemd drop-in override instead of editing the package's unit file directly:

```bash
sudo systemctl edit ssh
```

After changing unit configuration:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ssh
```

`daemon-reload` makes systemd reread unit definitions. It is not the same as reloading the SSH daemon's own configuration.

## 5.5 `systemctl` vs `service`

```bash
systemctl status ssh
service ssh status
```

`systemctl` is the native systemd management interface. The `service` command is a compatibility interface on many distributions and may forward operations to the active service manager.

**Good practice:** Use `systemctl` on a system that uses systemd.

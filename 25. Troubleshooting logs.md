# **Linux Logs – Which Log or Command Should I Use?**

Linux provides different commands and log files to investigate system problems. The important thing is to understand **what information you need and where Linux stores it**.

This cheat sheet covers `journalctl`, `/var/log`, `utmp`, `wtmp`, `btmp`, `dmesg`, and useful troubleshooting commands.

## **1. Decision table – What should I use?**

| What do you want to investigate?         | Command / Log                         | What it tells you                           |
| ---------------------------------------- | ------------------------------------- | ------------------------------------------- |
| Why is a service failing?                | `journalctl -u service`               | Logs for a particular service               |
| What errors happened recently?           | `journalctl -p err`                   | Error-level and higher-priority messages    |
| What happened before the current reboot? | `journalctl -b -1`                    | Logs from the previous boot                 |
| What happened during the current boot?   | `journalctl -b`                       | Current boot logs                           |
| Kernel, disk, driver or OOM issues?      | `journalctl -k` or `dmesg`            | Kernel messages                             |
| Who is logged in right now?              | `who` or `w`                          | Current login sessions                      |
| Who logged in previously?                | `last`                                | Historical login records                    |
| Who had failed login attempts?           | `lastb`                               | Failed login records                        |
| SSH, sudo or authentication problems?    | `journalctl` or `auth.log` / `secure` | Authentication-related logs                 |
| Apache, Nginx or application issues?     | `/var/log/` application logs          | Application-specific errors and access logs |
| Watch logs live?                         | `journalctl -f` or `tail -f`          | Continuously displays new log entries       |

**Quick rule:**

- `journalctl` → systemd journal logs.
- `/var/log` → traditional log files and application logs.
- `utmp` → current login sessions.
- `wtmp` → login/logout history.
- `btmp` → failed login attempts.

## **2. Understand each term**

### **A. journalctl**

`journalctl` is a command used to read logs collected by `systemd-journald`.

It can show logs from services, the kernel, system startup, authentication, and other system components.

**Useful commands:**

```
journalctl                  # View all available journal logs
journalctl -f               # Follow logs live
journalctl -n 50            # Show last 50 log entries
journalctl -u ssh           # Show SSH service logs
journalctl -u nginx         # Show Nginx service logs
journalctl -p err           # Show errors and more severe messages
journalctl -b               # Current boot logs
journalctl -b -1            # Previous boot logs
journalctl -k               # Kernel logs
journalctl --since today    # Logs since today
journalctl --since "1 hour ago"  # Logs from last hour
```

**Useful options:**

| Option    | Meaning                           |
| --------- | --------------------------------- |
| `-u`      | Filter by service/unit            |
| `-f`      | Follow logs live                  |
| `-n`      | Show the last N entries           |
| `-p`      | Filter by priority                |
| `-b`      | Filter by boot                    |
| `-k`      | Show kernel messages              |
| `--since` | Show logs after a specified time  |
| `--until` | Show logs before a specified time |

### **B. /var/log**

`/var/log` is the standard Linux directory where many traditional log files are stored.

Unlike `journalctl`, which reads the systemd journal, these are files you can inspect using commands such as `cat`, `less`, `grep`, and `tail`.

### **C. utmp – Current login sessions**

`utmp` is a binary file that stores information about users currently logged into the system.

- File location: `/var/run/utmp` (commonly linked to `/run/utmp`)
- It is read using commands such as `who` and `w`.
- It is not a normal text file, so don't open it with `cat`.

**Useful commands:**

```
who             # Who is currently logged in?
w               # Who is logged in and what are they doing?
users           # Display currently logged-in usernames
who -H          # Display headings with login information
```

### **D. wtmp – Login and logout history**

`wtmp` is a binary file that records historical login and logout events, including system boots and shutdowns.

- File location: `/var/log/wtmp`
- It is read using the `last` command.

**Useful commands:**

```
last                    # Show login history
last username           # Show history for a specific user
last -n 10              # Show last 10 records
last reboot             # Show reboot history
last shutdown           # Show shutdown history
```

### **E. btmp – Failed login attempts**

`btmp` is a binary file that records failed login attempts.

- File location: `/var/log/btmp`
- It is read using the `lastb` command.
- You may need `sudo` to read it.

**Useful commands:**

```
sudo lastb              # Show failed login attempts
sudo lastb -n 10        # Show last 10 failed attempts
sudo lastb username     # Filter failed attempts for a username
```

### **F. dmesg – Kernel messages**

`dmesg` displays messages from the Linux kernel's ring buffer. It is useful for investigating hardware, disks, drivers, memory, and device-related issues.

**Useful commands:**

```
dmesg                   # Display kernel messages
dmesg -T                # Show human-readable timestamps
dmesg -T | tail -50     # Show last 50 messages
dmesg -T | grep -i error
dmesg -T | grep -i "out of memory"
dmesg -T | grep -i usb
```

You can also use:

```
journalctl -k           # Kernel messages from the systemd journal
journalctl -k -b        # Kernel messages from current boot
journalctl -k -b -1     # Kernel messages from previous boot
```

**Difference:** `dmesg` reads the kernel ring buffer; `journalctl -k` reads kernel messages stored in the systemd journal. The journal can retain historical boot messages, while the ring buffer is not a replacement for persistent log storage.

### **G. auth.log / secure – Authentication logs**

These files contain authentication-related events such as SSH login attempts, sudo activity, and other authentication messages.

| Linux distribution          | Common log file     |
| --------------------------- | ------------------- |
| Ubuntu / Debian             | `/var/log/auth.log` |
| RHEL / CentOS / Rocky Linux | `/var/log/secure`   |

**Useful commands:**

```
sudo tail -f /var/log/auth.log
sudo grep -i "failed" /var/log/auth.log
sudo grep -i "accepted" /var/log/auth.log
sudo grep -i "sudo" /var/log/auth.log
```

On RHEL-based systems, replace `auth.log` with `secure`.

You can also check authentication messages through the journal:

```
sudo journalctl -u ssh
sudo journalctl -u sshd
sudo journalctl | grep -i "failed password"
```

Note: Ubuntu commonly uses the service name `ssh`; RHEL-based systems commonly use `sshd`. Journal availability and authentication logging configuration can vary.

### **H. Application logs – Apache, Nginx and others**

Applications often maintain their own log files under `/var/log`.

| Application            | Common log location                  |
| ---------------------- | ------------------------------------ |
| Apache (Ubuntu/Debian) | `/var/log/apache2/`                  |
| Apache (RHEL-based)    | `/var/log/httpd/`                    |
| Nginx                  | `/var/log/nginx/`                    |
| MySQL                  | Depends on configuration             |
| Custom application     | Depends on application configuration |

**Useful commands:**

```
ls -lh /var/log/              # List log files
sudo tail -f /var/log/nginx/error.log
sudo tail -f /var/log/nginx/access.log
sudo tail -f /var/log/apache2/error.log
sudo less /var/log/syslog
```

- `access.log` → Requests received by the web server.
- `error.log` → Errors and warnings generated by the web server.

## **3. Follow logs live – Monitor an issue as it happens**

Use these commands when you want to watch new log entries appear continuously.

```
journalctl -f                         # Follow system journal live
journalctl -u nginx -f                # Follow Nginx service logs
journalctl -u ssh -f                  # Follow SSH service logs
sudo tail -f /var/log/auth.log        # Follow authentication logs
sudo tail -f /var/log/nginx/error.log # Follow Nginx errors
```

**Difference:**

| Command         | Usage                                            |
| --------------- | ------------------------------------------------ |
| `journalctl -f` | Follow system journal                            |
| `tail -f file`  | Follow a specific log file                       |
| `tail -F file`  | Follow a file even if it is rotated or recreated |

## **4. Other useful log commands**

```
sudo less /var/log/syslog       # Read system logs (Ubuntu/Debian)
sudo less /var/log/messages     # Read general system logs (RHEL-based)
ls -lh /var/log/                # List log files and sizes
du -sh /var/log/                # Check total log directory size
sudo journalctl --disk-usage   # Check journal storage usage
sudo journalctl --vacuum-time=7d  # Remove archived journal data older than 7 days
```

**Useful journal priority levels:**

| Priority | Meaning       |
| -------- | ------------- |
| `0`      | Emergency     |
| `1`      | Alert         |
| `2`      | Critical      |
| `3`      | Error         |
| `4`      | Warning       |
| `5`      | Notice        |
| `6`      | Informational |
| `7`      | Debug         |

Examples:

```
journalctl -p err       # Errors and more severe messages
journalctl -p warning   # Warnings and more severe messages
journalctl -p info      # Informational and more severe messages
```

## **5. Real-time troubleshooting examples**

| Scenario                        | Commands to run                         |
| ------------------------------- | --------------------------------------- |
| SSH connection failing          | `sudo journalctl -u ssh -n 50`          |
| Nginx service not starting      | `sudo journalctl -u nginx -n 50`        |
| Server suddenly rebooted        | `last reboot` and `journalctl -b -1`    |
| Server running out of memory    | `journalctl -k \\| grep -i oom`         |
| Disk or driver issue            | `dmesg -T \\| tail -50`                 |
| Check failed login attempts     | `sudo lastb`                            |
| Check currently logged-in users | `who` or `w`                            |
| Check previous login history    | `last`                                  |
| Monitor SSH login attempts live | `sudo journalctl -f \\| grep -i ssh`    |
| Check authentication failures   | `sudo grep -i failed /var/log/auth.log` |

## **6. Important differences to remember**

| Term         | What it is                                    | Read using             |
| ------------ | --------------------------------------------- | ---------------------- |
| `journalctl` | Command to read systemd journal logs          | `journalctl`           |
| `/var/log`   | Directory containing traditional log files    | `less`, `cat`, `tail`  |
| `utmp`       | Current login session records                 | `who`, `w`             |
| `wtmp`       | Historical login/logout records               | `last`                 |
| `btmp`       | Failed login attempt records                  | `lastb`                |
| `dmesg`      | Command to read kernel ring-buffer messages   | `dmesg`                |
| `auth.log`   | Authentication log file on Ubuntu/Debian      | `less`, `grep`, `tail` |
| `secure`     | Authentication log file on RHEL-based systems | `less`, `grep`, `tail` |

**Remember these three commands:**

```
who       # Who is logged in now?
last      # Who logged in previously?
lastb     # Who tried and failed to log in?
```

**One important point:** Not every Linux distribution uses the same log files. Some systems rely heavily on `systemd-journald`, while others also use traditional text logs. Log retention, permissions and configuration can also differ. If a file such as `/var/log/auth.log` does not exist, check `journalctl` instead.

```
journalctl -xeu nginx
```

| Option       | Meaning         | Explanation                                           |
| ------------ | --------------- | ----------------------------------------------------- |
| `journalctl` | Journal command | Reads system logs                                     |
| `-x`         | Explain         | Shows additional explanatory messages, when available |
| `-e`         | End             | Jumps to the end (latest logs)                        |
| `-u`         | Unit            | Filters logs for a specific systemd unit/service      |
| `nginx`      | Service name    | Shows logs related to Nginx                           |

### **Useful examples**

```
journalctl -xeu nginx       # Troubleshoot Nginx
journalctl -xeu ssh         # Troubleshoot SSH
journalctl -xeu docker      # Troubleshoot Docker
journalctl -xeu kubelet     # Troubleshoot Kubernetes kubelet
```

### **When should you use it?**

Suppose Nginx is not starting:

```
sudo systemctl status nginx
```

You see that the service failed. Now run:

```
sudo journalctl -xeu nginx
```

This helps you identify the reason, such as:

- Port 80 is already in use.
- Configuration file has syntax errors.
- Permission denied.
- Missing files or directories.

**Easy way to remember:**

`journalctl -xeu service`

\= Show recent logs, jump to the end, provide explanations where available, and filter by the specified service.

# 12. User and Group Management

## 12.1 Linux user types

| Type | Purpose |
|---|---|
| Root user | Superuser with broad administrative privileges; UID 0 |
| System user | Usually created for services or applications |
| Normal user | Human login account, usually with a home directory |

When a user is created, Linux account databases store details such as:

- UID (User ID)
- Primary GID (Group ID)
- Home directory
- Login shell
- Account information

Relevant files:

| File | Purpose |
|---|---|
| `/etc/passwd` | User account records; does not normally contain password hashes |
| `/etc/shadow` | Password hashes and password-aging information; restricted access |
| `/etc/group` | Group records and supplementary group membership |
| `/etc/gshadow` | Secure group information |

## 12.2 Create users

```bash
sudo useradd -m konda
```

- `useradd` = create a user account
- `-m` = create the home directory if it does not exist

Ubuntu also provides the interactive helper:

```bash
sudo adduser konda
```

`adduser` typically asks for a password and optional user details. Its behaviour is distribution-specific; on Ubuntu it is a friendly front end for account creation.

## 12.3 Set or change a password

```bash
sudo passwd konda
```

## 12.4 Inspect users and groups

```bash
id konda
groups konda
getent passwd konda
getent group sudo
```

## 12.5 Add a user to a supplementary group

```bash
sudo usermod -aG devops konda
```

- `usermod` = modify a user account
- `-G devops` = set supplementary groups to include `devops`
- `-a` = append rather than replace the user's existing supplementary groups

**Important:** Use `-aG` when adding a group. Omitting `-a` can replace the existing supplementary group list.

Example: add a user to Ubuntu's `sudo` group:

```bash
sudo usermod -aG sudo konda
```

The user may need to log out and back in for the new group membership to apply to a new login session.

## 12.6 SSH password authentication

SSH server configuration is commonly stored in:

```text
/etc/ssh/sshd_config
/etc/ssh/sshd_config.d/*.conf
```

The effective setting may be influenced by included configuration files and directive ordering.

Check the effective setting:

```bash
sudo sshd -T | grep -i passwordauthentication
```

After changing SSH server configuration, validate it:

```bash
sudo sshd -t
```

Then reload the SSH service if validation succeeds:

```bash
sudo systemctl reload ssh
```

On Ubuntu the service is commonly named `ssh`. On some distributions it is `sshd`.

**Security note:** Enabling password authentication increases exposure to password-guessing attacks. Prefer SSH keys where appropriate, use strong unique passwords if passwords are enabled, and restrict access with firewall/security-group rules.

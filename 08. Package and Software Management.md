# 8. Package and Software Management

A **package manager** installs, upgrades, removes and tracks software packages and their dependencies.

Ubuntu and Debian use APT (`apt`) to manage `.deb` packages.

## 8.1 Common APT commands

```bash
sudo apt update                 # Refresh package indexes
sudo apt upgrade                # Upgrade installed packages
sudo apt install curl           # Install a package
sudo apt remove curl            # Remove a package, usually keeping config files
sudo apt purge curl             # Remove package and its system configuration files
sudo apt autoremove             # Remove automatically installed unused dependencies
apt show curl                   # Show package information
apt list --installed            # List installed packages
```

## 8.2 `update` vs `upgrade` vs `install`

```text
sudo apt update
      |
      v
Refreshes local package indexes from configured repositories.
It does not itself upgrade installed software.

sudo apt upgrade
      |
      v
Upgrades installed packages where possible using the refreshed indexes.

sudo apt install PACKAGE
      |
      v
Installs the requested package and required dependencies.
```

**Memory tip:** `update` updates the package information; `upgrade` updates installed software.


## `/usr/bin` vs `/usr/local/bin`

Both directories store executable commands, but they serve different purposes.

### 1. `/usr/bin`

- Stores general-purpose executable programs installed and managed by the operating system's package manager.
- On Ubuntu, tools installed using `apt` are commonly placed here.
- Examples: `curl`, `git`, `python3`.

### 2. `/usr/local/bin`

- Stores locally installed executables that are generally managed by the system administrator rather than the OS package manager.
- Commonly used for manually installed tools, custom scripts, and symbolic links.
- Examples: custom scripts, `terraform`, `kubectl`.

### 3. Practical example

Suppose Terraform's actual binary is stored in `/opt`:

```
/opt/terraform/terraform
```

Create a symbolic link:

```
sudo ln -s /opt/terraform/terraform /usr/local/bin/terraform
```

Now you can execute Terraform from any directory:

```
terraform version
```

**Why does this work?**

`/usr/local/bin` is normally included in the system's `PATH` environment variable. Linux finds the symbolic link there and follows it to the actual executable in `/opt`.

### 4. Quick comparison

| Directory        | Purpose                                           |
| ---------------- | ------------------------------------------------- |
| `/usr/bin`       | OS/package-manager-managed commands               |
| `/usr/local/bin` | Locally installed commands and custom executables |
| `/opt`           | Optional third-party software installations       |

**Remember:**

- `/opt` = Where software can be stored.
- `/usr/bin` = General system-managed commands.
- `/usr/local/bin` = Locally managed commands.
- `PATH` = Directories Linux searches to find commands.

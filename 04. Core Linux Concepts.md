# 4. Core Linux Concepts

These terms are related, but they do not mean the same thing.

## 4.1 Definitions

| Term | Definition |
|---|---|
| Program | Executable code stored on disk |
| Process | A running instance of a program, identified by a PID |
| Daemon | A process that usually runs in the background to provide a system or application function |
| Service | A managed unit of functionality, commonly controlled by systemd |
| Kernel space | Privileged execution environment where the Linux kernel runs |
| User space | Environment where normal applications and most system services run |
| System call | Interface through which a user-space program requests a kernel operation |
| systemd | System and service manager; normally PID 1 on Ubuntu |
| systemctl | Command-line tool used to communicate with systemd |

## 4.2 Program → process → daemon

```text
Program on disk
      |
      | Execute
      v
Process in memory
      |
      | If designed to provide a long-running background function
      v
Daemon
```

A daemon is a kind of process. Not every process is a daemon.

| ---------------- | --------------------------------------------------------- |
| `systemd`        | The system and service manager                            |

| `sshd` process   | The running instance of that program                      |

### **What does&#x20;**`ssh.service`**&#x20;actually tell systemd?**

For example, a service definition might contain:

```
[Unit]
Description=OpenSSH server

[Service]
ExecStart=/usr/sbin/sshd -D
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

This tells systemd things such as:

- What program to execute (`ExecStart`)
- What to do if it fails (`Restart`)
- When or under what conditions it should be started
- How it should be stopped and managed

Think of the service unit as the instructions, and systemd as the manager that follows those instructions.


A **unit** is the general concept in systemd. There are different types of units:

| Unit type  | Purpose                                            |
| ---------- | -------------------------------------------------- |
| `.service` | Manage services/processes                          |
| `.socket`  | Manage sockets and socket-based activation         |
| `.timer`   | Schedule activation at specific times or intervals |
| `.mount`   | Manage filesystem mount points                     |
| `.target`  | Group units together or represent system states    |

So technically, `ssh.service` is a **service unit**, and a service unit is one type of systemd unit.

> Systemd is the service manager in Linux. It manages services using unit files. A service unit defines how a program should be started, stopped, restarted, and monitored. For example, `ssh.service` defines how systemd manages the SSH daemon, `sshd`, which is the actual executable running as a process.

## 4.4 How a service relates to a daemon

A systemd service unit describes how systemd should manage a service workload. The workload may run a daemon process, but a service unit is not itself the executable process.

```text
systemd (service manager)
      |
      | manages
      v
ssh.service (unit definition)
      |
      | starts/manages
      v
/usr/sbin/sshd (program)
      |
      | running instance
      v
sshd process (PID)
```

The exact process model can vary. A service may also be one-shot, socket-activated or use other systemd mechanisms rather than running one continuously active daemon.

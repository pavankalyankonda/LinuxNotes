# 4. Core Linux Concepts

These terms are related, but they do not mean the same thing.

## 4.1 Definitions

| Term | Definition |
|---|---|
| Program | Executable code stored on disk |
| Process | A running instance of a program, identified by a PID |
| Daemon | A process that usually runs in the background to provide a system or application function |
| Service | service is a functionality provided by the system that runs in the background and serves a purpose, commonly controlled by systemd |
| Kernel space | Privileged execution environment where the Linux kernel runs |
| User space | Environment where normal applications and most system services run |
| System call | Interface through which a user-space program requests a kernel operation |
| systemd | System and service manager; normally PID 1 on Ubuntu |
| systemctl | Command-line tool used to communicate with systemd |

## **Service vs Daemon**

> A service is the functionality provided by a system. A daemon is a background program that provides that functionality. When the daemon executes, it runs as a process. A process is not necessarily a daemon, because ordinary foreground applications also run as processes.


## **What is a Daemon?**

A **daemon** (pronounced **DEE-muhn**) is a program designed to run in the background without requiring direct user interaction.

Its job is to provide a particular functionality, listen for requests or events, and perform tasks whenever needed.

Think of a daemon like an always-on personal assistant that works quietly in the background.

Some common examples:

- `sshd` – Handles remote SSH logins over the network.
- `httpd` – Runs a web server, delivering websites and APIs.
- `crond` – Manages scheduled tasks, such as automated backups and maintenance scripts.

By convention, many Linux daemon programs end with the letter `d`, which stands for "daemon".

A daemon is a program designed to run in the background. When it is running, it exists as a process with a PID.

## **What is a Service?**

A **service** refers to a functionality provided by the operating system or an application.

In Linux system administration, we also use the term service to refer to the managed unit that starts, stops, and monitors that functionality.

For example, SSH provides remote-access functionality. Linux uses `systemd` to manage this functionality through `ssh.service`.

A service can be implemented in different ways:

- It can start a daemon that keeps running in the background.
- It can start a process only when needed.
- It can execute a task once and exit.

Services can:

- Start automatically during system boot.
- Be started or stopped manually.
- Run continuously in the background.
- Execute a task and exit (oneshot).

## **Normal Services vs Oneshot Services**

Linux services can work in two common ways:

### **1. Normal service (continuously running)**

A normal service starts a process that usually keeps running in the background to provide functionality.

For example, SSH:

```
sudo systemctl start ssh
```

What happens?

1. Systemd starts the SSH service.
2. It launches the `sshd` daemon.
3. The daemon runs as a process with a PID.
4. It continuously listens for incoming SSH connections.

Running in background

In this case:

- Service: `ssh.service`
- Daemon: `sshd`
- Process: Running `sshd` instance

### **2. Oneshot service (runs once and exits)**

A oneshot service executes a task, completes it, and exits. It does not need a continuously running daemon.

For example, creating a backup directory:

```
[Service]
Type=oneshot
ExecStart=/usr/bin/mkdir -p /backup
```

What happens?

1. Systemd starts the service.
2. It executes the `mkdir` command.
3. The directory is created.
4. The process exits.
5. Systemd remembers that the task completed successfully.

Task completed

You might see:

```
Active: active (exited)
```

This means the task completed successfully, but the process is no longer running.

### **Comparison**

| Feature   | Normal service                | Oneshot service        |
| --------- | ----------------------------- | ---------------------- |
| Execution | Runs continuously (typically) | Runs a task once       |
| Process   | Usually stays running         | Exits after completion |
| Daemon    | Commonly uses one             | Does not require one   |
| Example   | SSH (`sshd`)                  | Creating a directory   |


A normal service commonly uses a daemon to provide its functionality continuously. A oneshot service simply executes a task and exits. This is why a service does not always mean a daemon.

## **Key differences to remember**

| Term    | What it means                                                                          |
| ------- | -------------------------------------------------------------------------------------- |
| Service | Functionality provided by the system; also commonly refers to its managed systemd unit |
| Daemon  | A background program designed to provide functionality                                 |
| Process | An instance of a program currently executing                                           |


**The easiest way to remember:**

- Service = What functionality is provided?
- Daemon = What background program provides it?
- Process = What is actually running right now?

# 4. Core Linux Concepts

These terms are related, but they do not mean the same thing.

## 4.1 Definitions

| Term | Definition |
|---|---|
| Program | Executable code stored on disk |
| Process | A running instance of a program, identified by a PID |
| Daemon | A process that usually runs in the background to provide a system or application function |
| Service | service is a functionality provided by the system that runs in the background and serves a purpose, commonly controlled by systemd |
| Kernel space | Privileged execution environment where the Linux kernel runs |
| User space | Environment where normal applications and most system services run |
| System call | Interface through which a user-space program requests a kernel operation |
| systemd | System and service manager; normally PID 1 on Ubuntu |
| systemctl | Command-line tool used to communicate with systemd |

## 4.2 Program → process → daemon

```text
Program on disk
      |
      | Execute
      v
Process in memory
      |
      | If designed to provide a long-running background function
      v
Daemon
```

A daemon is a kind of process. Not every process is a daemon.


## 4.3 How a service relates to a daemon

A systemd service unit describes how systemd should manage a service workload. The workload may run a daemon process, but a service unit is not itself the executable process.

```text
systemd (service manager)
      |
      | manages
      v
ssh.service (unit definition)
      |
      | starts/manages
      v
/usr/sbin/sshd (program)
      |
      | running instance
      v
sshd process (PID)
```


## **Service vs Daemon vs Process**

These three terms are related, but they describe different things.

### **1. Service — What functionality is being provided?**

A **service is a functionality provided by the system that runs in the background and serves a purpose.**

Examples:

- SSH service → Allows remote users to connect to a Linux server.
- Web service → Serves websites to users.
- Cron service → Runs scheduled tasks.

### **2. Daemon — What program provides that functionality?**

A **daemon is a background program that provides a particular functionality, usually without direct user interaction.**

For example, `sshd` is the daemon that provides SSH functionality.

### **3. Process — What is actually running?**

A **process is a running instance of a program.**

When the `sshd` program is executed, Linux creates a process that runs in memory and performs its work.

### **Example: SSH**

```
SSH Service
   |
   | Provided by
   v
sshd (Daemon / Background program)
   |
   | Executed and running
   v
sshd (Process)
```

| Term    | SSH example                     |
| ------- | ------------------------------- |
| Service | SSH remote-access functionality |
| Daemon  | `sshd` background program       |
| Process | Running instance of `sshd`      |

### **How systemd fits in**

`systemd` is the service manager. It manages services by starting, stopping, restarting, and monitoring them.

```
systemd
   |
   | manages
   v
SSH Service
   |
   | runs
   v
sshd (Daemon)
   |
   v
Process
```



| A service is the functionality provided by a system. A daemon is a background program that provides that functionality. When the daemon executes, it runs as a process. A process is not necessarily a daemon, because ordinary foreground applications also run as processes. |

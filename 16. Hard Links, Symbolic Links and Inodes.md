# 16. Hard Links, Symbolic Links and Inodes

## 16.1 What is an inode?

An **inode** is a filesystem data structure that stores metadata about a file, such as:

- File type and permissions
- Owner and group IDs
- File size
- Timestamps
- Link count
- Pointers/references to the file's data blocks

A filename is stored in a directory entry that maps the name to an inode number. The filename itself is not stored as part of the inode.

Inspect inode numbers:

```bash
ls -li
```

## 16.2 Hard link

A **hard link** is another directory entry that points to the same inode as an existing file.

```bash
ln file1 hardlink1
ls -li file1 hardlink1
```

Both names should show the same inode number.

If you remove one name, the other name still refers to the same file data:

```bash
rm file1
cat hardlink1
```

The data remains available because another hard link still references the inode.

The filesystem can reclaim the file's data after the link count reaches zero and no process still has the file open.

**Limitations:** Hard links normally cannot cross filesystem boundaries, and creating hard links to directories is generally prohibited for ordinary users.

## 16.3 Symbolic (soft) link

A **symbolic link** is a special file containing a path to another file or directory.

```bash
ln -s file1 softlink1
ls -l softlink1
```

If the target is removed or moved, the symbolic link may become broken (dangling).

```bash
rm file1
ls -l softlink1
```

## 16.4 Hard link vs symbolic link

| Feature | Hard link | Symbolic link |
|---|---|---|
| Points to | Same inode | A pathname |
| Inode number | Same as target | Usually different |
| Can cross filesystems | No | Yes |
| Can link directories | Normally not for ordinary users | Yes |
| If original filename is removed | Other hard link still works | Link may break if target path disappears |

## 16.5 Use a symbolic link to expose a script in PATH

Suppose a script is stored here:

```text
/home/konda/scripts/hello.sh
```

Make it executable:

```bash
chmod +x /home/konda/scripts/hello.sh
```

Create a symbolic link in `/usr/local/bin`:

```bash
sudo ln -s /home/konda/scripts/hello.sh /usr/local/bin/hello
```

If `/usr/local/bin` is in your `PATH`, you can run:

```bash
hello
```

This is useful because you can keep the script in your own project directory while making a command name available system-wide.

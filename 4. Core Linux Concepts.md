# 4. Core Linux Concepts

These terms are related, but they do not mean the same thing.

## 4.1 Definitions

| Term | Definition |
|---|---|
| Program | Executable code stored on disk |
| Process | A running instance of a program, identified by a PID |
| Daemon | A process that usually runs in the background to provide a system or application function |
| Service | A managed unit of functionality, commonly controlled by systemd |
| Kernel space | Privileged execution environment where the Linux kernel runs |
| User space | Environment where normal applications and most system services run |
| System call | Interface through which a user-space program requests a kernel operation |
| systemd | System and service manager; normally PID 1 on Ubuntu |
| systemctl | Command-line tool used to communicate with systemd |

## 4.2 Program → process → daemon

```text
Program on disk
      |
      | Execute
      v
Process in memory
      |
      | If designed to provide a long-running background function
      v
Daemon
```

A daemon is a kind of process. Not every process is a daemon.

## 4.3 How a service relates to a daemon

A systemd service unit describes how systemd should manage a service workload. The workload may run a daemon process, but a service unit is not itself the executable process.

```text
systemd (service manager)
      |
      | manages
      v
ssh.service (unit definition)
      |
      | starts/manages
      v
/usr/sbin/sshd (program)
      |
      | running instance
      v
sshd process (PID)
```

The exact process model can vary. A service may also be one-shot, socket-activated or use other systemd mechanisms rather than running one continuously active daemon.
